Game formulas

How the game turns its data into the numbers you see. Read from the game's own code (client 1.1.146); names in code are the game's. Time is in frames, 30 per second. The game calculates in 32-bit floats, and "cut" means the fraction is dropped (toward zero).

Deploy cost

deploy cost = unit cost + class cost

The unit's own cost (3, 4 or 5) is only its share; the class tier adds its own (job_data.cost: Warrior 11, Guardian (sword & shield) 19, Sniper (bow) 8 …). Example: Platina 5 + Guardian 19 = 24. Awakening nodes like "Deploy cost −1" and cost-down effects in battle come on top of this. PlayerData.Setup, PlayerData.get_Cost

Base stats (HP, ATK, DEF, MDEF)

level rate = clamp((level − 1) / max level, 0, 1)
stat = cut( (class min + (class max − class min) × level rate) × unit % / 100 )

The class tier gives the range (job_data.minLife … maxMagicDefense); the unit card gives a percentage for each stat (unitcard.life, power, defense, magicDefense, about 110–130). Note the rate divides by the max level, not max level − 1, so even at max level it is a little under 1 (149/150). Equipment, the personal weapon's level bonuses and abilities are added afterwards. There is no separate magic attack: magic classes use ATK. PlayerData.Setup, PlayerData.CalcBaseParam

Max levelrarity max level (30 for every rarity) + the rank bonus of the highest rank (rank 5: +120) = 150

Skill levels

levels  = highest level in the skill's recipe + 1   (no recipe: 1 level)
rate    = (level − 1) / (levels − 1)                (only 1 level: rate = 1, the max values)

The number of levels comes from the skill's upgrade recipe (recipe_skill), not from the skill's own maxLevel field: every unit skill has 5 levels, including the 100 skills (mostly second skills) whose maxLevel says 1. Skill.CalcParamRate, SkillDataBase.GetMaxLevel

Cooldown, duration and cost at a level

value = cut( rate × max + (1 − rate) × min )        (in frames; ÷ 30 for seconds)

For minCoolTime/maxCoolTime, minDurationTime/maxDurationTime and minCost/maxCost. The OC skill's cooldown uses the parent skill's rate. Example: Platina's Dullahan Form, 1470 → 1350 frames: 49, 48, 47, 46, 45 s. Skill.CalcParamRate, Skill.CalcValueByParamRate

Effect values at a level

maxParam = 0  →  value = param (no change with level)
otherwise      v = (1 − rate) × param + rate × maxParam
               value = the next whole number if it is within 0.1 of it, else v cut

Each effect (talent) has param (level 1) and maxParam (last level). Example: Soul Blade ATK +20 % → +50 %: level 2 = 27.5 → 27 (not within 0.1 of 28), so ×1.2, ×1.27, ×1.35, ×1.42, ×1.5. A few skills have add_max_level: past that level the value goes on from maxParam toward addMaxParam (no unit skill uses it now). cAbilityTalent.CreateTalentData, SnapToNearestInt

Stats in battle

Stat = A × B + C          (then kept inside the stat's limits)

A = the stat before battle            (Base stats above)
B = (1 + Normal %) × (1 + Map %) × (1 + Prayer %) × (1 + Extra %)
C = flat buffs − flat debuffs
  • A: the unit's own stat from her class tier and level, plus awakening, equipment and the personal weapon's level bonus.
  • B: every buff and debuff belongs to one of four groups (Normal, Map, Prayer, Extra). Inside a group the % values add up; the groups multiply. Each group's % = its % buffs − its % debuffs.
  • C: fixed amounts ("ATK +100") are added once, after the %.
  • A debuff on a target with resistance is smaller: debuff × (100 − resistance) / 100.
  • Only the highest counts (no adding) for Attack speed % and Move speed %. That is why the game has a separate "attack speed (stacks)" effect for the ones meant to add.
  • A "…Fixed" effect (for example range fixed) replaces the result.
  • ATK, DEF and MDEF in battle stay between 50 % and 1000 % of A, and debuffs on them are made smaller by the target's "base status" resistance.
  • "In the party" effects are added the same way before the battle, so they are already inside A.
  • The unit's skills and traits are most likely Normal; which effects use Map, Prayer and Extra is not checked yet.

Example: ATK 1000, a skill ATK +20 % and a trait ATK +30 % (both Normal), and ATK +100: 1000 × (1 + 0.5) + 100 = 1600. BuffParamData.CalcParamNum, UpdateTargetParam, IsMaxRateTarget

Damage

Damage = ( the larger of  H − D ,  H × 10 % ) × (1 − cut₁ %) × (1 − cut₂ %) × …

H    = ATK × (1 + up₁ %) × (1 + up₂ %) × … × Crit × E
Crit = crit damage %  (150 % = ×1.5)      only on a critical hit; otherwise ×1
E    = element: ×1.2 advantage, ×0.8 disadvantage, otherwise ×1
D    = target's DEF (physical), MDEF (magic), 0 (true damage)
  • ATK: the attacker's ATK in battle (Stats in battle). A skill's "ATK ×1.8" is an ATK buff, so it is already in here. An effect that "deals X % of ATK" hits with X % of ATK instead.
  • Damage up %: each effect is its own (1 + up %), and they multiply: +20 % and +30 % = 1.2 × 1.3 = +56 %, not +50 %. They count before DEF. A target's own "damage taken up" when hit counts here too.
  • Crit: a hit is critical if a random number 0–99 is below the attacker's crit chance + the target's extra crit chance taken. Crit damage starts at 150 % (+50 %), cap 300 %, plus the target's extra crit damage taken. A crit multiplies H, so it also counts before DEF.
  • E: from the game's settings (#11 = 120, #12 = 80).
  • D: DEF or MDEF in battle. True damage (Ignore DEF, 防御無視) skips it.
  • 10 % floor: a hit never does less than 10 % of H, however high the DEF.
  • Damage cut %: each effect is its own (1 − cut %), and they also multiply: −30 % and −30 % = 0.7 × 0.7 = −51 %, not −60 %, so cuts can never reach 100 %. They count after DEF and after the floor. "Damage taken +10 %" is a cut of −10 %: ×1.1.
  • Each step drops the fraction. After that: a fixed-damage effect replaces the number, then cover (an ally takes the hit), barrier, and HP.

Example: ATK 2000, damage up +20 %, a crit (150 %), element advantage → H = 2000 × 1.2 × 1.5 × 1.2 = 4320. Target DEF 1500 and damage cut 30 %: (4320 − 1500) × 0.7 = 1974. Same hit on DEF 5000: 4320 − 5000 is below 432, so 432 × 0.7 = 302. DamageCalculater.DamageAction; TalentOption.GetResult / CalcRateValue (Damage = Rate: 1.0 × each v / 100); TalentActionDamageUp (BeforeCalc 9/10), TalentActionDamageCut (BeforeDamage 13/14); BattleObject.EvaluateCritical, AttackData.SetCritical; CharacterType.GetAttributeRate

How the data stores themthe whole multiplier, not the %: damage up 120 = +20 %, 80 = −20 %; damage cut 70 = cut 30 % (the damage that gets through), 110 = takes +10 %. A second value, if there, is the chance the effect works
Barrier (AddBarrier)absorbs damage until broken. First value = what the amount is based on: 0 a fixed amount, 1 % of max HP, 2 % of ATK; second value = the amount

Ailments

How an ailment lands depends on its group. R = the target's resistance to that ailment (0–100).

Stun: a gauge (no dice)

gauge = gauge + build-up × (100 − R) / 100        stunned when the gauge reaches 100
build-up 100 or more: stunned at once, R is not used
R = 100: never stunned
  • Values: [build-up, duration]. The texts' words: low ≈ 8–15, medium ≈ 35, large ≈ 50, very large ≈ 80.
  • Build-up 100 (stuns in one hit, even through high resistance): Donne skill 1 (on activation, enemies in range; her text doesn't say it) and Seren skill 2.
  • The stun's duration is shortened by a second "stun time" resistance, which enemies only get from effects.

TalentActionAddStun.ActExecute, CharaStatus.AddStun (StunThreshold = 100), CharacterStatusResistance.IsMax

Chance: Poison, Burn, Freeze, Petrify, Darkness, Curse, Launch

lands if  a random number 0–99  <  chance × (100 − R) / 100
R = 100: immune

"Ailment chance up" effects raise the chance. The texts' words (rarely, low, medium, high) follow no rule: 20 % is called "rarely", "low" or "medium" on different units, so the wiki shows the numbers.
