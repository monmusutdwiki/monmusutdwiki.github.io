Game formulas

How the game turns its data into the numbers you see. Read from the game's own code (client 1.1.146); names in code are the game's. Time is in frames, 30 per second. The game calculates in 32-bit floats, and "cut" means the fraction is dropped (toward zero).

Deploy cost

deploy cost = unit cost + class cost

The unit's own cost (3, 4 or 5) is only its share; the class tier adds its own (job_data.cost: Warrior 11, Guardian (sword & shield) 19, Sniper (bow) 8 …). Example: Platina 5 + Guardian 19 = 24. Awakening nodes like "Deploy cost −1" and cost-down effects in battle come on top of this. PlayerData.Setup, PlayerData.get_Cost

Base stats (HP, ATK, DEF, MDEF)

level rate = clamp((level − 1) / max level, 0, 1)
stat = cut( (class min + (class max − class min) × level rate) × unit % / 100 )

The class tier gives the range (job_data.minLife … maxMagicDefense); the unit card gives a percentage for each stat (unitcard.life, power, defense, magicDefense, about 110–130). Note the rate divides by the max level, not max level − 1, so even at max level it is a little under 1 (149/150). Equipment, the personal weapon's level bonuses and abilities are added afterwards. There is no separate magic attack: magic classes use ATK. PlayerData.Setup, PlayerData.CalcBaseParam

Max levelrarity max level (30 for every rarity) + the rank bonus of the highest rank (rank 5: +120) = 150

UnitCommonDataManager.GetMaxLevel; unit_rarity.maxLevel, unit_rank_info_table.addMaxLevel, property Game_PlayerProp_MaxUnitRank = 5

The game's stat panel (潜在覚醒 view): Lv. Max = class 5, max level, with every awakening node that changes a stat (HP, ATK, DEF, MDEF, range, attack speed, deploy cost, crit); Lv. 1 = class 1, level 1, no awakening. Neither includes equipment, sub skills or the personal weapon.

Skill levels

levels  = highest level in the skill's recipe + 1   (no recipe: 1 level)
rate    = (level − 1) / (levels − 1)                (only 1 level: rate = 1, the max values)

The number of levels comes from the skill's upgrade recipe (recipe_skill), not from the skill's own maxLevel field: every unit skill has 5 levels, including the 100 skills (mostly second skills) whose maxLevel says 1. Skill.CalcParamRate, SkillDataBase.GetMaxLevel

Cooldown, duration and cost at a level

value = cut( rate × max + (1 − rate) × min )        (in frames; ÷ 30 for seconds)

For minCoolTime/maxCoolTime, minDurationTime/maxDurationTime and minCost/maxCost. The OC skill's cooldown uses the parent skill's rate. Example: Platina's Dullahan Form, 1470 → 1350 frames: 49, 48, 47, 46, 45 s. Skill.CalcParamRate, Skill.CalcValueByParamRate

Effect values at a level

maxParam = 0  →  value = param (no change with level)
otherwise      v = (1 − rate) × param + rate × maxParam
               value = the next whole number if it is within 0.1 of it, else v cut

Each effect (talent) has param (level 1) and maxParam (last level). Example: Soul Blade ATK +20 % → +50 %: level 2 = 27.5 → 27 (not within 0.1 of 28), so ×1.2, ×1.27, ×1.35, ×1.42, ×1.5. A few skills have add_max_level: past that level the value goes on from maxParam toward addMaxParam (no unit skill uses it now). cAbilityTalent.CreateTalentData, SnapToNearestInt

Damage cut and damage up

DamageCut vdamage taken × v / 100: 40 = takes 40 % (−60 %); over 100 = takes more
DamageUp vdamage dealt × v / 100: 150 = ×1.5

Time

All times (cooldowns, durations, ACT duration, redeploy) are frames at 30 per second: 450 frames = 15 s.
